## Transfer across processes and languages

Test file: 3,145,984 bytes. The native Go client and Python probe retrieved
the same content from the Go server.

```text
SHA-256: 679361bf172a2b2f3d48919ee7b2b6fea9cf6e351005736ac7274ac8fde4e0f2
TLS: TLS 1.3
Negotiated group (Go client): X25519MLKEM768
Negotiated cipher: TLS_AES_128_GCM_SHA256
Authentication: Ed25519 (classical)
ALPN: deep/1
```

The probe used Python 3.14.6 with OpenSSL 3.5.7. Python does not publicly expose
the negotiated group: for that connection, the Go server enforces and verifies
X25519MLKEM768. The probe explicitly trusts the test certificate; it is not a
second complete implementation of adapters and pinning.

## Reproduce

```powershell
go test ./...
go vet ./...
go test -race ./...
go test -run '^$' -fuzz '^FuzzReadFrame$' -fuzztime=3s -parallel=2
.\bin\deep.exe demo
```

The race detector requires a compatible C compiler. For cross-process tests,
use `init`, `serve`, `fetch`, and the probe described in
[`interop/README.md`](../interop/README.md). Running `deep.exe` normally does not
require Python, an installed Go toolchain, or external OpenSSL.

Connections between physical computers and execution on Linux/macOS were not tested.
No external cryptographic audit was performed, and the Windows URI association was not changed.
